# Ads by Kanapiya — RU / EN

Статический сайт на основе предоставленного макета: русский по умолчанию, переключение на английский, 31 услуга с подробными страницами, архив кейсов (14 демонстрационных сценариев сохранены, но скрыты), 28 клиентов, тарифы в USD / RUB / KZT и форма заявки в мессенджеры.

React, шрифты, стили и логотипы хранятся локально. npm-зависимости, API-ключи, база данных и сервер приложений не нужны.

## Локальный запуск

Нужен Node.js 20 или новее:

```sh
node scripts/serve.mjs
```

Откройте http://127.0.0.1:4173. Проверка: `node scripts/check.mjs`. Сборка: `node scripts/build.mjs`. Также доступны `npm run dev`, `npm run check`, `npm run build`.

## GitHub Pages

1. Загрузите содержимое проекта в репозиторий GitHub, включая `.github`.
2. Используйте ветку `main` или `master`; для другого имени измените `branches` в `.github/workflows/deploy.yml`.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. Запустите **Actions → Deploy portfolio to GitHub Pages → Run workflow**, если файлы уже были загружены до настройки Pages.
5. Адрес опубликованного сайта появится в **Settings → Pages**.

Workflow проверяет и собирает сайт, затем публикует только `dist`. Пути относительные: поддерживаются и корневой домен, и `username.github.io/repository/`. Детальные страницы используют hash-маршруты, поэтому прямое открытие и обновление работают на GitHub Pages без серверных редиректов.

```text
index.html?lang=ru
services.html?lang=ru
services.html?lang=ru#/services/seo
cases.html?lang=en
cases.html?lang=en#/cases/python-reporting
clients.html?lang=ru
reviews.html?lang=ru
about.html?lang=ru
```

## Отзывы, биография и обложки

Тексты и данные находятся в **`site/assets/profile-data.js`**:

- `ABOUT_PROFILE` — имя, фото, описание, навыки и публичные источники биографии. Основа: личный блог Kanapiya.ru и материалы автора по digital-маркетингу. Все тексты доступны в RU/EN и редактируются вручную.
- `REVIEWS` — отзывы. `published: false` скрывает запись; `platform` выбирает иконку Google, Яндекс, 2ГИС, Zoon, собственного сайта или другого источника. `rating: null` не выводит звёзды. Шаблон — `examples/review.template.json`.
- `kind: "summary"` означает явно подписанный пересказ публичного отзыва. Для предоставленного полного текста используйте `kind: "original"`. На карточке текст ограничен четырьмя строками, в попапе показывается целиком. `sourceUrl` ведёт на оригинал.
- `REVIEW_GOOGLE` — ссылки владельца и проверенный снимок рейтинга **5,0 / 41 отзыв на 06.10.2026**. Это ручные данные, они не обновляются автоматически. Без входа Google показал пять текстовых отзывов; они включены в подборку, плюс один отзыв из Kanapiya.kz. Архив показывает все добавленные записи, ссылка на Google — остальные отзывы. Непроверенные отзывы с Яндекса, 2ГИС и Zoon не добавлены.
- `CLIENT_COVERS` — обложки клиентов. Поле `image` у отдельного кейса имеет приоритет. При отсутствии обложки используются логотип или монограмма клиента. Изображения локальные, источники — `site/assets/media/SOURCES.json`.

Лента отзывов на главной движется бесконечно, останавливается по кнопке, наведению, фокусу и открытию попапа. Касание на телефоне останавливает движение для ручной прокрутки. При системном ограничении анимации остаётся обычная горизонтальная лента. В архиве работают поиск и фильтр по площадке. Окно закрывается крестиком, Escape или нажатием на фон с возвратом фокуса.

## Форма заявки

Контакты в `site/assets/config.js`: WhatsApp **+7 707 340 68 88**, Telegram **@muhamed_kanapiya**.

Посетитель выбирает услугу, вводит имя, контакт, необязательный адрес сайта и описание задачи. Под формой виден готовый текст. Кнопка открывает адрес владельца в выбранном мессенджере с заполненным черновиком; посетитель нажимает «Отправить» в самом мессенджере. Автоматическая отправка в оба канала не выполняется. Можно скопировать текст, если приложение не поддерживает предзаполнение.

В черновик автоматически включается **«Страница заявки»** — адрес страницы, где находится форма. Если посетитель пришёл через кнопку «Обсудить задачу» с услуги, кейса или другой страницы, добавляется **«Переход к форме»**. Источник переносится параметром `from` без cookies и истории просмотров. В адресах остаются только публичные параметры маршрута (`lang`, `post`, `category`) и идентификатор услуги/кейса в hash; посторонние query-параметры не передаются. Внешний или чужой путь в `from` отбрасывается. Обе строки одинаково входят в WhatsApp, Telegram и скопированный текст.

Кнопки тарифов заранее выбирают услугу и включают тариф в сообщение. Поля сохраняются при переключении языка и валюты на странице, но не записываются в localStorage и не отправляются на сервер. В localStorage хранятся только язык и валюта. Контактные данные появляются в URL мессенджера только после нажатия соответствующей кнопки.

Форматы ссылок: [WhatsApp click to chat](https://faq.whatsapp.com/5913398998672934), [Telegram public username links](https://core.telegram.org/api/links#public-username-links).

## Цены вручную — без курсов

Все цены находятся в **`site/assets/prices.js`**. Значения USD, RUB и KZT независимы: изменение доллара не меняет рубли или тенге. В файл перенесены последние отображавшиеся суммы; теперь это фиксированные числа, которые можно заменить своими.

```js
plans: {
  audit: { USD: 49, RUB: 4101, KZT: 21939 },
  launch: { USD: 350, RUB: 29291, KZT: 156706 },
  management: { USD: 250, RUB: 20922, KZT: 111933, adSpendPercent: 10 }
}
```

`plans` — три тарифа на главной и в сообщении заявки. `services` — пакеты конкретных услуг; ключи совпадают с ID услуги и названиями пакетов. Например, `services["search-ads"].Setup.KZT` задаёт стоимость настройки поисковой рекламы в тенге.

Число `0` показывает нулевую цену, `null` означает «По запросу». Вводите числа без символов валюты и пробелов. `suffix` задаёт дополнительный текст, например `+10%`. `adSpendPercent` управляет процентом бюджета в тарифе ведения; `0` убирает доплату. Курсы валют, внешние запросы к банку и пересчёт отсутствуют. Основной переключатель меняет только отображаемую валюту. Показатели кейсов не пересчитываются.

## Как скрывать демо и добавлять реальные кейсы

В **`site/assets/config.js`** установлено:

```js
showDemoCases: false;
```

Демо-кейсы скрыты на главной, в архиве, в похожих кейсах и по прямым ссылкам. Демонстрационные KPI услуг также скрыты. На первом экране показана схема работы вместо модельных показателей. Вернуть примеры можно значением `true`; они сохранят заметную пометку «Демонстрационный кейс».

Реальные кейсы добавляются в **`site/assets/cases.js`**, массив `window.REAL_CASES`. Готовый шаблон — **`examples/real-case.template.json`**. Скопируйте его объект в массив, заполните реальные сведения и переключите `published` на `true`. До этого запись остаётся черновиком и нигде не отображается.

- `id`: уникальный адрес латиницей, например `client-seo-2026`.
- `clientId`: ID клиента из `site/assets/clients.js`; связывает карточку клиента со всеми его опубликованными кейсами.
- `serviceIds`: ID выполненных услуг, например `["seo", "web-development"]`; на странице кейса появляются ссылки на эти услуги.
- `category`: `ads`, `seo`, `analytics`, `web`, `automation`, `training` или `research`.
- `featured`: показывать раньше других кейсов на главной.
- `title`, `headline`, `tag`: название, краткий результат, ниша/география/период. Объекты `{ru, en}` содержат обе языковые версии.
- `metrics`: подтверждённые показатели `metric`, `before`, `after`, `delta`. Можно оставить пустой массив, если количественных данных нет.
- `wrong`, `did`, `timeline`: исходная ситуация, выполненные работы, этапы и сроки; каждый пункт поддерживает `{ru, en}`.

Для подготовки кейса достаточно прислать клиента, ссылку, услугу, географию, период, задачу, выполненные работы, показатели до/после и подтверждения. Бюджет и название клиента публикуются только если их можно раскрывать. При нехватке данных оставляйте поле пустым; вымышленные числа не нужны.

Страница кейса показывает паспорт проекта, диаграммы и таблицу «до / после», списки проблем и выполненных работ, этапы со сроками и другие кейсы того же клиента. Диаграммы строятся только по числам из `metrics`: поддерживаются одиночные значения и диапазоны (`$12-18`, `0.8-1.5%`, `1500-4000`). У пары «до / после» общая шкала от нуля, тёмная часть полосы — диапазон. При несовместимых единицах или нечисловых значениях остаётся таблица. Помесячные значения автоматически не создаются.

Карточки клиентов содержат логотип, название и описание. Нажатие на карточку открывает попап со списком связанных опубликованных кейсов и ссылкой на сайт клиента с UTM. На компьютере и телефоне поведение одинаковое; наведение не раскрывает кейсы. Попап закрывается крестиком, Escape или нажатием вне окна, затем фокус возвращается на карточку. Каждый кейс ведёт на подробную страницу. Якорь `clients.html?lang=ru#client-kilc` ведёт к конкретной карточке.

## Таблица цен

В каталог добавлены `meta-ads`, `shopify`, `insales`, `training`, `crm-integrations` и `python-scraping`. У каждой услуги есть страница на RU/EN, состав работ, этапы и FAQ. Обучение — одна услуга с тремя форматами: индивидуальным, групповым и корпоративным. Формат выбирается в форме заявки и включается в черновик сообщения. Новые цены в `site/assets/prices.js` пока равны `null` («По запросу»); каждую валюту заполняйте отдельно.

`pricing.html` — отдельная страница с пакетами всех услуг, составом работ, сроками и ценами из `site/assets/prices.js`. Есть поиск по русским и английским названиям, фильтры направления и типа цены, сортировка по стоимости, переключение USD / RUB / KZT и страницы по 12 строк. «По запросу» остаётся в конце при сортировке по цене, нулевая цена считается указанной. На телефоне таблица прокручивается по горизонтали внутри своего блока. Ссылки на страницу добавлены в меню, футер и блок стоимости главной.

## UTM-метки внешних ссылок

Все внешние HTTP(S)-ссылки получают `utm_source=ads_by_kanapiya`, `utm_medium=referral`, `utm_campaign=portfolio`. Эти значения меняются в `outboundUtm` файла `site/assets/config.js`. `utm_content` отличает переходы с карточки клиента (`client-kilc`), страницы кейса (`case-kilc-seo`), плавающей кнопки (`floating-whatsapp`) и формы (`contact-form-telegram`). Исходные параметры адреса, якорь и текст заявки сохраняются. Внутренние ссылки, `tel:` и `mailto:` не получают UTM. Отображение атрибуции на стороне получателя зависит от его аналитики; сами UTM не создают события GA4 на вашем сайте.

## Клиенты и анимации

`site/assets/clients.js` содержит список владельца. На главной выводятся **9 клиентов с `featured: true` + «Ваш проект»**: две строки по пять на большом экране. На планшете и телефоне сетка адаптируется. Лимит регулируется `featuredClientsLimit` в конфигурации; полный список находится на `clients.html`. Названия и описания владельца сохранены.

18 логотипов сохранены с официальных сайтов, источники — `site/assets/logos/SOURCES.json`. Остальные компании представлены монограммами; они же показываются при ошибке загрузки изображения. Логотипы принадлежат их правообладателям и используются для идентификации клиентов.

Главная содержит плавное появление первого экрана, блоков при прокрутке и отклики карточек. При `prefers-reduced-motion: reduce` анимации отключаются. Без IntersectionObserver контент остаётся видимым. Кнопки WhatsApp и Telegram закреплены справа снизу; подсказки доступны при наведении и фокусе клавиатуры. Они открывают прямой чат, отдельно от формы заявки.

## Страница автора

Все данные страницы `about.html` редактируются в `window.ABOUT_PROFILE` файла **`site/assets/profile-data.js`**:

- `timeline` — год, тип события, заголовок и описание на RU/EN. `url` ведёт к источнику; `certificateId` вместо ссылки открывает сертификат с таким `id`.
- `certificates` — название, год, организация (`issuer`), тип участия, описание, путь `image` и ссылка на оригинал `sourceUrl`. Скан положите в `site/assets/media/certificates/`; карточка и попап появятся автоматически.
- `education` — дополнительные курсы без выдуманных дат и подтверждений.
- `github.projects` — выбранные публичные репозитории и описания; статистика GitHub не подгружается и не имитируется.
- `socialLinks` — реальные адреса профилей, подписи и иконки (`telegram`, `x`, `code`, `globe`, `github`, `whatsapp`). Прямые WhatsApp и Telegram берутся из `config.js`.

Таймлайн основан на архиве HackDay, личном блоге, профиле GitHub и трёх опубликованных там сертификатах. DevFest — сертификат спикера, IdeaForge — командный выход в финал, C-DAC — завершение 80-часового курса. Они не обозначены как профессиональная сертификация Google Ads. Копии документов хранятся локально; источники записаны в `site/assets/media/SOURCES.json`. Попап закрывается крестиком, Escape или нажатием снаружи, затем возвращает фокус на карточку.

## Мегаменю, футер и служебные страницы

Описания пунктов мегаменю берутся из `short` соответствующей услуги в `reference-app.js` или `catalog.js`. Заголовок, эмоджи и подпись ведут одной ссылкой на страницу услуги. На компьютере меню открывается по нажатию, на телефоне направления работают как раскрывающиеся группы. Длинное меню прокручивается внутри панели.

Футер содержит отдельные колонки направлений, портфолио, социальных ссылок и информации. Список ссылок находится в `FooterDirectory` файла `utilities.js`; соцсети используют `profile-data.js`. Случайные фразы редактируются в `FOOTER_THOUGHTS` на RU/EN. Кнопка «Ещё мысль» выбирает другую фразу без повторения текущей. Это короткие тексты для сайта, а не цитаты, приписанные известным людям. Кнопка «Наверх» появляется после прокрутки, сохраняет текущий адрес услуги/кейса и учитывает настройку уменьшения анимации.

Тексты служебных страниц находятся в `UTILITY_PAGES` файла `utilities.js`. Обновляйте их при подключении аналитики, сервера форм или изменении хранения данных. Для `404.html` задан `<base href="/portfolio/">`, чтобы ресурсы работали даже на вложенном неверном адресе. При смене имени репозитория измените base; для сайта в корне домена используйте `/`. На localhost base автоматически становится `/`.

## Блог: как посмотреть и редактировать

Блог доступен по прямым адресам и через страницу «Все страницы». Прямых ссылок на статьи или архив в главной навигации, мегаменю и футере нет. На GitHub Pages:

- [Архив всех статей](https://muhamed-kanapiya.github.io/portfolio/blog.html?lang=ru).
- [Рубрика «Аналитика»](https://muhamed-kanapiya.github.io/portfolio/blog-category.html?lang=ru&category=analytics).
- [Рубрика «Реклама»](https://muhamed-kanapiya.github.io/portfolio/blog-category.html?lang=ru&category=advertising).
- [Рубрика «Сайты и автоматизация»](https://muhamed-kanapiya.github.io/portfolio/blog-category.html?lang=ru&category=web).
- [Статья с таблицей, вкладками, аккордеоном и списками](https://muhamed-kanapiya.github.io/portfolio/blog-post.html?lang=ru&post=measurement-plan).

Локально запустите `node scripts/serve.mjs` и откройте `http://127.0.0.1:4173/blog.html?lang=ru`. Меняйте `lang=ru` на `lang=en` либо используйте переключатель языка. Карточки архива ведут к остальным статьям. Неизвестный адрес статьи/рубрики показывает сообщение со ссылкой на архив.

Все материалы находятся в **`site/assets/blog-data.js`**. В `BLOG_CATEGORIES` задаются рубрики. В `BLOG_POSTS` каждая статья содержит постоянный `slug`, рубрику `category`, дату `date`, заголовок `title`, анонс `excerpt`, текст обложки `cover`, теги и разделы `sections`. Тексты задаются через `blogText("Русский", "English")`. `status: "draft"` скрывает статью из архива, похожих материалов и прямого просмотра; `published` показывает её. Эти файлы публичны, поэтому черновики не предназначены для конфиденциальных текстов.

Разделы содержат уникальные `id`, заголовки и массивы `blocks`. Типы блоков: `paragraph`, `list` (с `ordered: true` для нумерации), `table`, `tabs`, `accordion`, `callout`, `quote`, `code`. Оглавление строится из разделов, время чтения — из длины текста выбранного языка. Полоса сверху отражает прогресс чтения. Похожие статьи сначала выбираются из той же рубрики. Обложки — редактируемая типографика с эмоджи, без внешнего сервиса изображений.

Блок автора использует `ABOUT_PROFILE`. Комментарии пока работают **только как предпросмотр**: форма проверяет имя и текст, показывает карточку на этой странице, ничего не отправляет и не сохраняет после обновления. Реальных опубликованных комментариев и серверной модерации в статической версии нет.

На трёх страницах блога установлен `noindex, follow`, пока вы проверяете материалы. Это просьба поисковым системам, а не защита доступа. Когда блог будет готов к индексации, удалите этот meta-тег из трёх HTML-файлов и добавьте нужные ссылки в навигацию.

### Последующий перенос в WordPress

Данные отделены от оформления, но текущий сайт не является готовой темой WordPress. При переносе:

1. Создайте записи из `BLOG_POSTS`: `slug` → ярлык, `title` → заголовок, `excerpt` → отрывок, `date` → дата; рубрики и теги перенесите в соответствующие таксономии.
2. Перенесите текстовые блоки в Gutenberg: абзацы, заголовки, списки, таблицы, цитаты и код. Вкладки и аккордеоны воспроизведите блоками выбранной темы/плагина либо собственными блоками. Оглавление и время чтения можно вычислять из содержимого записи.
3. Воссоздайте шаблоны архива, рубрики и отдельной записи в теме; подключите штатные комментарии с модерацией и данные профиля автора. RU/EN потребуют выбранного решения для многоязычности.
4. Настройте перенаправления старых адресов с параметрами `post`/`category` на новые постоянные ссылки, затем проверьте меню, UTM, формы и мобильную версию.

Поля записей для будущего импорта описаны в [официальной документации WordPress REST API](https://developer.wordpress.org/rest-api/reference/posts/).
